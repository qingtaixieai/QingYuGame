# 青屿 · 大世界探索试玩

当前试玩版：2～10人、同一六角大陆、自由探索、全图可见、账号审批、服务器存档、采集背包、聊天室和基础局部战斗。战斗暂不结算生命、伤害或胜负，也没有交易和NPC模拟。青屿为实现中的暂用展示名称，不改变完整战棋设计。

## 技术与目录

- `frontend/`：TypeScript、React、PixiJS 8；全图浏览、地点目录、像素角色、在线状态、管理后台。
- `backend/`：Java 21、Spring Boot 4.1、PostgreSQL、Flyway、WebSocket。
- `scripts/`：本地启动、集成验证、发布打包。
- `deploy/`：原生systemd部署文件、Docker Compose备选模板及Nginx配置。

## 开发启动

需要 Node.js 22.12+、JDK 21+、Maven 3.6.3+、PostgreSQL 17。

1. 创建 PostgreSQL 数据库与非超级用户，配置 `DATABASE_URL`（JDBC连接串）、`DATABASE_USER`、`DATABASE_PASSWORD`。
2. 首次启动设置 `ADMIN_USERNAME`、随机强密码 `ADMIN_PASSWORD`。数据库已有管理员时不会通过环境变量覆盖密码。
3. 本地设置 `APP_ORIGIN=http://127.0.0.1:5173`、`SECURE_COOKIE=false`，仅监听本机。
4. 在 `backend` 运行 `mvn spring-boot:run`。
5. 在 `frontend` 运行 `npm ci` 和 `npm run dev`，访问 `http://127.0.0.1:5173`。不要使用 localhost：本机可能另有IPv6服务。

本次工作环境已建立 `.local/` 下的隔离 PostgreSQL 测试实例（127.0.0.1:55432）；`scripts/start-backend.ps1`使用其配置。测试管理员凭据在被忽略的 `.local/dev.json`，不用于生产。

## 验证

- `cd backend && mvn verify`：编译、100个种子的地图连通/通行检查、相同种子可复现、非法目的地检查。
- 本地后端运行后：`cd scripts && npm ci && npm run smoke`。仅针对隔离本地数据库，创建9个测试账号，与管理员构成10人联测，涵盖审批、越权、CSRF、移动、落库、离线、撤权、密码重置、原子重建和过期世界指令。此测试会重建本地世界，不要改为生产地址。
- 测试报告输出到 `.local/integration-report.json`。

## Docker备选部署

`scripts/package-release.ps1`生成 `.local/qingyu-release.tar.gz`，只包含构建结果与部署模板，不含密码、测试数据或私钥。在目标服务器解压到 `/opt/qingyu`。

1. 先检查实际系统、现有服务、端口和磁盘。旧服务的替换已获授权，但清理必须针对核实的具体服务，不做整机盲删。
2. 创建 `/opt/qingyu/.env`（权限600），按 `deploy/env.example`填写域名、数据库密码和初始管理员密码，密码应分别随机生成。
3. 在该目录运行 `docker compose up -d`。PostgreSQL无公网端口，Java只绑定本机18080；容器内存上限合计约1.1GB。
4. 将 Nginx 模板中的 `DOMAIN`替换为真实域名并启用；用 `nginx -t`检查。
5. 使用有效证书配置HTTPS及HTTP跳转，确认WebSocket升级、反向代理头和cookie的Secure属性。生产环境不得关闭Secure cookie。
6. 外部访问注册→管理员审批→两名玩家同时移动→退出重登，验收生产数据保存。

`docker compose restart game`保留数据；不要使用`docker compose down -v`，它会删除世界数据库。
旧服务无需备份不代表新世界无需备份：上线后建议定期将PostgreSQL备份保存到独立存储。

## 规则与边界

- 地图使用轴向六角坐标；平原、森林、丘陵、海岸与桥梁可通行，高山、海洋、河流不可直接通行。
- 每步由服务器定时推进并先提交数据库，再发送给客户端。动画插值只影响画面。
- 单个世界所有变更串行处理；世界重建和全部角色位置重置在同一数据库事务中完成。客户端指令带世界版本，拒绝旧地图指令。
- 密码使用BCrypt；cookie为HttpOnly、SameSite=Strict，生产要求Secure；数据库仅保存会话令牌哈希。修改请求校验自定义头与Origin，WebSocket校验同源及账号准入。
- 登录和注册有限速。所有管理员操作校验权限并写审计记录；密码重置会废止旧会话。
- 离线角色保留、不挡路；未进入世界的待审批账号不出现在地图中。
- 管理员初始密码通过部署环境设置，后台不提供重置管理员自身密码功能，避免管理者被误踢出；维护时通过受控数据库操作恢复。
- 现阶段按10人目标实现，定期广播在线玩家快照；还没有分区服务器、跨节点事务、角色视野过滤或万人容量保证。正式角色视野规则将在完整设计实现时接入。
- `WorldMap`为独立领域逻辑；`WorldService`为首版世界状态归属边界，后续可按区域/战场拆分。拆分需要真实协议、并发与故障恢复设计，不能直接多开同一个应用指向同一数据库。
- 基础局部战斗已接入服务器回合与战术点；环境物理和完整战棋规则仍属后续设计与实现范围。

## 战斗操作与渡船探索（2026-09-24）

战斗底部操作栏分别开启移动与攻击模式。移动范围按剩余行动点及占用格动态计算：第一次点击可达格，用青绿色路线预览路程及行动点消耗；第二次点击同一格才沿最短路移动，每格1点。预览时点其他格只取消路线，恢复可移动范围，下一次点击再选新目的地。范围提示只在对应模式显示；结束回合后收起。顺序条非当前卡片整体灰显，当前卡片放大，切换时平滑缩放。

普通攻击每次预设消耗2点，目标为相邻格（允许空格），点击以鼠标下的六边格为准，人物与名字不拦截格子选择。一回合可多次预设，但每人同时只保留一个红格：改选未触发的红格会取消旧预设、再扣2点且不退款；已触发后可再次预设。重复点击已预设的同一格不重复收费。进入红格不会触发；其他角色离开红格、攻击者走出与红格相邻的范围、或攻击者下一次正常回合到来时，结算同一次预设攻击并清除。格内无人则落空，不能攻击自己。本阶段仍不计算血量或伤害。多格移动会逐格处理攻击触发。

首次启动新版时，旧大陆向外扩展至半径34，在新海域生成一座随机方向、随机内部地形的岛屿，并在可从出生点步行到达的旧海岸增加望潮港。旧地形、道路、地点与玩家坐标保留。全地图可见；港口与远屿浅滩之间的海路固定。

玩家在港口共同投入木头和石头建造公共渡船，材料达到要求后自动开航。渡船不限人数，空船也往返；两岸停靠时手动上下船，离线仍在船上。船上不能移动、采集、发起/加入战斗或发送地图表情，聊天仍可用。停靠点正在战斗时暂时不能下船。服务停止期间航行计时暂停，最多约1秒的存档间隔误差。
