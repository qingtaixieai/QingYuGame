# 工程协作入口

本目录是当前协作规则，历史阶段交付文档是证据，不是当前任务指令。玩法由用户决定，工程负责人不能自行增加玩法。

1. [团队协作](团队协作.md)：谁负责、谁集成、谁验收。
2. [模块边界](模块边界.md)：文件归属、依赖与共用规则。
3. [接口协作](接口协作.md)：HTTP、WebSocket、内部动作和数据库对接。
4. [开发验收](开发验收.md)：本地运行、检查、发布和回滚。
5. [任务与交接模板](任务与交接模板.md)：可直接复制的代理任务、交付和决策记录。
6. [本轮重构计划](../superpowers/plans/2026-10-29-engineering-refactor.md)：阶段进度和验收记录。
7. [协作贡献流程](../../CONTRIBUTING.md)、[后端入口](../../backend/README.md)、[前端入口](../../frontend/README.md)：按职责接任务。

当前功能基线为本地提交 `f7f831a`，迁移V30；工程化三阶段已本地完成，见[交付记录](../工程化重构交付_20261029.md)。未推送或部署，发布状态仍以实际发布记录为准。

设计正文：[设计统合](../设计统合_20261023_NPC与后勤.md)、[设计补齐](../设计补齐与实施交接_20261023.md)、[决策总账](../设计决策总账_20261022.md)。最新确认优先；发现冲突先记录，不把历史“未授权”应用到当前已授权任务。

参考依据：[微软游戏职业分工](https://developer.microsoft.com/en-us/games/resources/industry-careers/)、[GitLab设计评审流程](https://handbook.gitlab.com/handbook/engineering/architecture/workflow/)、[OpenAPI接口描述](https://learn.openapis.org/specification/)。青屿采用轻量团队流程，未引入这些公司的全部组织制度。
