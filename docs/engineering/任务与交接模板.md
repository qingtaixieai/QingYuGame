# 任务、交接与决策模板

## 任务单
```text
ID / 标题：
状态：待确认 / 已授权 / 实现中 / 待验收 / 已验收 / 已发布
用户确认来源：
负责人 / 独立验收人：
目的和可观察结果：
允许修改的文件：
不能修改的文件/玩法：
上游输入契约（字段、函数、错误）：
下游输出契约：
验收场景（正常、拒绝、重试、NPC/玩家）：
验证命令、环境、是否破坏数据：
依赖/阻塞/未确定事项：
```

## 代理交接
```text
工作区、分支、基线提交：
已修改文件及原因：
接口变化及调用方：
测试命令、退出码、日志：
静态审查结论（与运行测试分开）：
已知限制、未覆盖、待修复：
本地提交 / 已推送 / 已部署：
下一步及禁止重复的操作：
```

## 决策记录
```text
编号 / 日期 / 状态（建议、确认、被替代）：
背景和约束：
候选方案与取舍：
决定（用户确认还是工程判断）：
影响模块及接口：
验证方式和撤销条件：
替代的旧决定 / 被哪个决定替代：
```

## 本轮真实任务示例
任务：拆分登录、游戏协调、管理页面。负责人客户端；主代理集成；独立代理验收。输入为现有Account和State协议；输出是App、Game、Admin组件导出。保持CSS顺序、WebSocket唯一连接及清理、战斗请求序号，不能改变玩法。验收含构建、已有地图/物品测试、两种屏幕实际登录。具体文件以[重构计划](../superpowers/plans/2026-10-29-engineering-refactor.md)和实际提交为准。
