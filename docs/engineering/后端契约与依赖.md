# 后端契约与依赖（2026-11-06）

保持Spring Boot单进程，WorldService锁、事务、广播和NPC/玩家共用动作链不变。

## 可执行契约

- `GameplaySerializationContractTest`：序列化真实Character、Loadout、EquipmentItem、BattleSummary、BattleActor、BattleIntent、BattleEvent record；读取当前`frontend/src/shared/protocol.ts`检查必填顶层字段和Java primitive的JSON形状。支持当前单行对象声明及Hex交叉类型，不支持的声明须显式扩展解析器，不静默跳过。
- `HttpContractIntegrationTest.inventoryAndSocketStateMatchClientRequiredFields`：在隔离数据库注册临时角色，检查真实背包查询结果及WebSocket所使用的`world.snapshot(viewer)`状态体的前端必填字段。该测试不建立真实WebSocket连接，不代表握手、断线重连或广播时序已验证。
- `contracts/http-routes.json`及原HTTP测试继续检查84条路由、权限与错误响应。

本轮修正的类型差异：背包`Item.move_rule`对应数据库查询列；武器/预设攻击仍使用`moveRule`。`Loadout.offhand`对应`EquipmentItem`（camelCase装备摘要），不是含quantity和snake_case列的背包Item。未改变服务端响应字段或玩法。

这些检查不声称覆盖全部嵌套对象、引用非空性、枚举取值、所有接口或业务语义。增加字段时应同时修改协议与相应测试。

## 依赖约束

`scripts/backend_boundary_check.py`守护现有六个纯规则模块：WorldMap、SceneTopology、NpcCombatNavigation、NpcPolicy、LogisticsPolicy、WeaponRules。禁止引入Spring、SQL/JdbcTemplate、WorldService、SocketConfig、WebSocketSession和Controller依赖。扫描忽略注释/字符串，缺失受保护文件也报错。

该检查已接入`engineering_check.py`，现有CI会执行。它是明确范围的源码防线，不是完整Java调用图或所有跨领域依赖证明。生产服务仍在同一Java包，后续拆分必须保持现有事务边界。

## 验证

在仓库根运行`python -m unittest discover -s scripts -p "test_*.py"`及`python scripts/engineering_check.py`。
后端运行`mvn verify`；数据库集成部分必须显式设置本地`PHASE1_DATABASE_URL`，格式和清理边界见[开发验收](开发验收.md)。本轮使用单独的`qingyu_phase1_pixel_engineering_20261106`库，不能指向真实存档或线上库。
