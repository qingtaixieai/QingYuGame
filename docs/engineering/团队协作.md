# 团队协作

角色是职责，不代表新增了真实员工或常驻代理。人员可兼任；作者不能代替独立验收人。主代理负责总集成，用户决定玩法和优先级。

|角色|输入|交付物|负责验收|
|---|---|---|---|
|制作人（用户）|体验、建议、冲突|已确认需求和取舍|玩法、可用体验|
|主程/集成负责人（主代理）|已确认需求、模块报告|任务分配、接口协调、合并、发布事实|跨模块一致性|
|世界/场景负责人|地块、室内、通行规则|地图、设施、移动和船运|场景回归|
|战斗/角色负责人|动作和装备规则|唯一动作处理器、回合、伤害与状态|玩家/NPC一致性|
|NPC/经济负责人|任务和供需规则|决策、后勤、交易和实物账务|生命周期和幂等|
|客户端负责人|已确认交互、接口契约|页面、渲染、手机横屏|浏览器实际操作|
|测试/发布负责人|任务验收条件、候选提交|独立审查、运行证据、回滚检查|阶段放行|

## 一项任务如何流转
确认需求 → 主代理登记范围和接口 → 责任人实现并自测 → 跨模块对接 → 独立验收 → 修复和复验 → 主代理集成 → 记录本地/仓库/线上状态。

- 一次任务一个主负责人；多个代理不能同时写同一文件。WorldService、公共协议和迁移由主代理协调。
- 下游依赖未完成时可以按已确认契约写测试，但不得编造服务返回当作联调通过。
- 任务分支以 `codex/` 开头；在同一工作区协作时登记文件所有权，不互相覆盖未提交修改。
- 每个阶段只有独立验收明确通过才放行。额度耗尽/工具报错/无结论均不是通过。
- 本机 Claude 桥默认 `flash`、`analyze`，禁止Pro和Shell。编辑须在明确任务授权范围内单独分配；不把只读审查当作运行测试。
- 代理工具和权限见[插件与子代理交接](../插件与子代理交接.md)，不用为本规范重新安装。

## 冲突处理
以用户最新明确决定为准；工程证据用当前代码和运行结果核对。跨模块变更先由接口提供方与使用方对齐，再合并。不能凭过去对话中的数字选项猜需求。建议、已确认、已实现、已测试、已发布分别记录。
