# 开发与验收

环境：JDK21+、Maven3.6.3+、Node22.12+（直接执行TypeScript测试推荐Node24）、Python3.11+、PostgreSQL17。生产凭据不写入任何文档或任务提示。

## 常用命令（仓库根目录）
```text
python -m unittest discover -s scripts -p "test_*.py"
python scripts/engineering_check.py
node --experimental-strip-types --test scripts/battle-inventory.test.mjs scripts/ferry-motion.test.mjs scripts/map-gestures-test.mjs scripts/scene-geometry.test.mjs
```
前端在frontend目录执行 `npm ci`、`npm run build`；后端在backend目录执行 `mvn verify`。

后端数据库集成测试必须设置 `PHASE1_DATABASE_URL=jdbc:postgresql://127.0.0.1:端口/qingyu_phase1_隔离名称`，用户名worldgame、密码local-only仅用于一次性本地测试库。这些测试会清理/重建数据，不能指向开发主存档或服务器。没有该变量时部分集成类跳过，不能称为完整验证。CI创建临时PostgreSQL服务并显式传变量。

本机现有JDK/Maven位置和启动方式见[开发检查工具](../开发检查工具.md)。本地网页登录环境与破坏性测试数据库分开；更新后端JAR后必须重启对应测试服务，不能只刷新浏览器便声称新版后端已验证。

## 从玩家反馈到试玩验收

涉及地图切换、界面和玩法联动时，用一条完整的玩家路线组织需求和验收。青屿本轮采用「从大陆进入白石城 → 沿街找到旅店 → 进店休整 → 在原场景开战 → 从原门返回」。

1. **从玩家的问题出发。** 对照实际截图和源码，记录玩家进入每个场景后能否认出自己的位置、目标和下一步动作。截图记录窗口大小、缩放和面板状态。可以另开对话做独立只读诊断。
2. **先分角色评审，再请用户确认方案。** UI 负责信息优先级和桌面、横屏布局，UX 负责场景动线、地标和切图镜头，前后端负责核对路径、门、服务条件和存档。主代理用实际规则解决分歧，列出修改范围、分工和验收路线，经用户确认后开工。
3. **按文件归属并行实现。** 本轮分为场景绘制、大陆操作区与路线接口、局部场景与战斗画布。主代理对齐共享组件和接口，合并时核对门格、碰撞、角色落点以及服务状态是否与服务器一致。
4. **独立审查、修复、复验。** 审查代理记录可定位的阻塞，实施者修复后由审查代理复核。本轮复核了移动改道的过期路线、设施相邻格重算、倒地时操作可用性、战斗位置同步及撤离标记。代理调用报错时记录结果，重试或改用可用的独立审查。
5. **在实际页面走完路线。** 用同一版本在 1280×800 桌面和 844×390 横屏登录操作。检查选中时只预览路线、到达后按钮切换、休整完成或取消、从原门返回。港口检查造船明细可展开和收起。二、三级开战前后检查是否复用同一个 PixiJS 画布，再用真实输入验证战斗移动。写入测试只在隔离库进行，截图复审与浏览器操作结果分别记录。

本轮记录了 159 项后端测试、12 项前端几何与道具测试、86 条 HTTP 路由检查，以及桌面和横屏的实际操作结果。横屏全房视角下的角色头顶文字仍偏小，列为后续视觉复验项。实现范围和验收证据见[场景连续性实施计划](../superpowers/plans/2026-11-11-scene-continuity.md)。
