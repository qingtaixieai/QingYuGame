# 接口协作

接口正文是[前后端接口文档](../前后端接口文档.md)。[HTTP路由清单](../../contracts/http-routes.json)记录本次重构前的完整方法/路径集合，工程检查拒绝路由消失、重复和未登记新增。它不是完整OpenAPI，不验证请求/响应类型。

## 提供方和使用方必须共同确认
每项接口变更记录：方法/路径、请求字段和可空性、响应字段、权限、错误码/中文消息、版本或幂等要求、事件刷新、兼容策略、双方测试。先更新契约再实现两端，不能只改一侧。

HTTP通过 accounts.require 做身份/审批/管理员检查；写操作沿用 RequestGuard 的Origin/CSRF校验。路径迁移不能降低检查等级。保留原始错误状态和message；普通聊天接口与原GameController的账号缺失提示有历史差异，重构要分别兼容。

WebSocket保持现有 `/ws` 连接与消息结构，新增字段先保证旧消费者可忽略。变更状态消息或生命周期必须验证断线清理、重连、战斗切换和重复事件。不能随意把定时广播改成异步调度。

## 内部动作
NPC决策提供actor/目标/行动，公共动作负责距离、AP、物品、场景、回合和结算。AI只选动作，不作为权威验证器。后勤/交接的实物转移、成本和回执使用同一事务，重试不可重复扣物。

## 示例：装备道具变更
1. 策划确认类别、代价、目标和失败行为。
2. 战斗/物品负责人共同定义后端字段及唯一执行入口。
3. 前端负责人按字段展示可用/禁用与结果，不重复推算权威数值。
4. 测试覆盖普通玩家、NPC、非法目标、重复请求、装备变化。
5. 主代理核对文档、迁移、回归和兼容，再集成。

## 架构决策记录
使用[模板](任务与交接模板.md)记录背景、候选方案、决定、代价及撤销条件。重要决定需引用用户确认；工程细节可由负责人决定并明确标注，不写成用户确认。
