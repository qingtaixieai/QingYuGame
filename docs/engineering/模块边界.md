# 模块边界

代码保持一个后端进程和数据库。模块按职责分工，不引入网络调用或重复数据模型。机器可检查的文件归属在 [module-ownership.json](../../config/module-ownership.json)。逻辑负责人名称不是GitHub账号，不能直接填进CODEOWNERS冒充审批人。

|模块|当前核心入口|允许依赖|禁止行为|
|---|---|---|---|
|平台集成|WorldService、SocketConfig、RequestGuard|各领域公开动作|在HTTP/WebSocket重复实现领域结算|
|账户/社交|AccountService、ChatService、ModerationService|账户、世界通知|绕过审批、会话或管理权限|
|世界/场景|WorldMap、SceneRuntime、SceneService、TownService、FerryService|角色位置、通行、持久化|客户端决定真实坐标|
|战斗/角色|BattleService、CombatActions、WeaponRules、CharacterService|装备、状态、场景、战报|NPC另写免AP/免距离战斗|
|NPC/后勤|NpcDirector、LogisticsDirector、LawService|读取世界、调用共用动作|直接瞬移交货或复制实物|
|经济/物品|HandoverService、LootService、ShopService、ProductionService|角色、数据库、物品目录|绕过库存、交接同意或重复结算|
|客户端体验|frontend/src|传输契约、展示逻辑|作为伤害、权限和物品余额权威|

WorldService暂保留串行化与跨领域事务编排；领域模块不能私自引入另一把锁或异步提交。BattleService暂保留回合状态机。重构拆出能独立负责的适配、展示、战报职责，不以“全面”名义重写所有稳定算法。

新文件必须有唯一归属；工程检查会拒绝无主和多主后端源文件。前端统一由客户端负责人负责，其内部分工按 app（启动/认证）、features（游戏/管理/战斗）、components（纯展示）划分。共享协议不依赖UI组件，UI通过类型导入协议。

涉及持久化时，新迁移由集成负责人分配下一个版本；不得改V1–V30。涉及共享动作时提交调用路径证据：玩家输入和NPC决策应汇入同一执行/校验函数。
