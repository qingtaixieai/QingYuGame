## 物件行动反馈（2026-11-21）

短行动以单批不超过 10 秒判定，进度放在实际物件头顶，仅本人可见。随身制作、休整和携带尸体的操作放在本人头顶。长行动使用既有右上地点卡，只有对应格与组件被选中时显示进度与停止。查看其他格、进入移动选格不会中断，合法路线实际发起才中断物件行动；随身制作和吟唱沿用各自已确认规则。

`shared/actionProgress.ts` 负责任务身份、场景、目标和单批时钟，`components/ActionFeedback.ts` 负责 Pixi 进度与结果展示，`shared/actionResults.ts` 负责新结果筛选和去重。服务端结果驱动成功暖色亮点与浮字、失败红闪原因、停止灰字。首次和重连快照只补日志。进度开始、结束与批次变化唤醒活动层，倒计时不重建地形。

旅途闲话中的「旅途日志」同时保留个人行动记录与战斗明细。货箱页显式取得查看权，按箱串行开关请求，令牌保护旧页面关闭。占用和补货状态显示在对应地点卡／货箱页，库存由服务端结算。

更新于 2026-11-19。以本地 `codex/online-scene-pixi-20261110` 工作树、实际前端源码和连接 V36 隔离后端截取的画面为依据。用于设计评审和后续开发交接，当前正式服版本应另行核对。

## 项目是什么

青屿是横屏网页上的多人开放世界战棋。玩家在同一大世界旅行，经由大陆地块进入可探索的局部地图，再经城内门口进入房间。地图承担旅行、观察、位置、移动和就地互动。玩家可以在地块上接触地点、资源、运输、旅人和战利品。战斗把同一处局部场景切到回合制，行动点、选格和先攻条进入前景。玩家可以切回大世界观察，战斗状态由服务端继续维护。

画面用清浅草绿、沙土黄和浅蓝区分地形，森林、石块、房屋、船和角色用像素形体表现。界面以米白信息卡和深绿操作按钮为主。旅店沿用像素和六边坐标，用木地板、墙和柜台传达室内空间。棋盘网格帮助玩家判断距离和位置，河流、沿街建筑与家具负责说明场景是什么。

## 界面怎么组织

- **地图在中心。** 左上标识当前地图，右边提供缩放、查看全图和定位。顶部保留青屿品牌、联机状态和战斗视角切换。横屏适配提供树形顶部横栏开关，侧边栏可收起，地点操作区随视口尺寸调整。
- **地点与交互。** 点地图或目录先得到位置和路线状态，到达以后显示进入、通过门、采集、休整或上船等动作。不同状态共用地点操作卡，格子可挂多个交互组件。端到端移动与是否合法由服务端判定；地图高亮表示候选和反馈。
- **侧边栏。** 承载大陆手记、同行旅人、人物、聊天和图鉴。装备、背包和制作从人物页进入；战斗记录与聊天共用入口。图鉴用卡片展示游戏内对象与组件。管理员入口按账号权限展示。
- **动作栏。** 场景探索有可收起的底部栏，战斗中展示行动点、通用／武器／道具／技能／法术／职业槽位和结束回合。攻击与移动先标候选格，战斗移动可先看路径与消耗，再确认同一目标。昵称、血量、目标和命中反馈在 Pixi 画布内展示。
- **输入。** 桌面以点击、拖动和滚轮为主，横屏手机以触摸、拖动和双指缩放为主。交互按 1280×800 与 844×390 检查；关键状态以文字、图标或描边配合颜色表达，避免只靠颜色识别。

前端为 React 19、TypeScript、Vite 和 PixiJS 8。CSS/React 管理可操作界面，Pixi 绘制地图空间、角色与动画。大陆用 `MapView`，二三级用 `SceneView` 挂同一 `SceneCanvas`；带 `sceneId` 的战斗在该场景挂 `BattleView`，并提供共享画布控制。没有 `sceneId` 的战斗保留独立 `SceneCanvas` 入口。单独交付的 Opus HTML 原型是 Canvas 2D 草图，实际游戏前端的技术基线使用上述 Pixi 模块。

地图、角色、占位、门、战斗和资源状态从后端 HTTP 与 WebSocket 取得。UI 可以预览路线、渲染动画、过滤候选格，执行和结算仍走现有接口及共用校验，玩家与 NPC 使用同套规则。涉及路径、坐标、回合、权限或库存的界面改动应核对[接口说明](../前后端接口文档.md)和[模块归属](../../config/module-ownership.json)。

## 本轮确认与后续设计判断

- 已连接本机隔离库，使用临时账号实际进入大陆、白石城和旅店，再在旅店开战。两个尺寸均截图，浏览器无页面异常，且同图战斗前后 Canvas 节点一致。夹具将临时角色置于城镇和门口，完整步行、真机输入、正式服和性能未在本轮验证。
- 当前横屏旅店的地点卡横跨地图中央，和底部探索栏一起压缩可见空间。优先处理地点卡展开方式和默认显示内容。白石城入口镜头应先能看懂街道走向、广场位置与旅店所在街边，再提高装饰密度。
- 后续版式仍以现有 Pixi 场景与后端数据为基准。先让玩家在三层地图都能完成「看懂位置 → 选目标 → 到达 → 互动」，再用街区和室内功能区提高画面辨识度。影响渲染的调整按同场景复跑前后性能样本。

## Opus 审阅记录

主代理运行游戏并采集双尺寸画面。Claude Opus 5.5 通过 Kiro 收到 `Game.tsx`、`MapView.tsx`、`SceneView.tsx`、`SceneCanvas.tsx`、`BattleView.tsx`、交互组件与依赖清单的对应源码，以及大陆、白石城、旅店、战斗四张实际画面。第二次精简请求以高强度自适应推理完成。该 API 调用没有本地浏览器权限，运行结论来自主代理的隔离浏览器记录。

采用 Opus 对场景视觉连续性、地图与 React 控件分工、窄屏工具栏的观察。复核源码后修正它对层级命名、独立战场及截图验证范围的误读。地图总规模、触控手势通过情况和低端机帧率仍需实测，未从截图推定。

## 当前实装 · 白石城样板

- 视觉与界面基线采用正俯视像素地图、轻边线六边格、米白地点卡与深绿控件。地点卡当前在右上，详情默认折叠，主要动作与格内组件可直接访问。底部探索栏保留折叠按钮。横屏入城镜头为热栏预留空间，复验时入口人物在热栏上方。
- 样板画面从南侧主路连到中央石板广场，水井居中，旅店在右侧。[`districtArt.ts`](../../frontend/src/districtArt.ts) 按需加载一个图集，裁成屋顶、树冠、井、摊位、花箱、栅栏等可复用贴图。`SceneView` 按场景版本接入，`sceneArtLayout.ts` 只处理绘制用的地貌，没有改写服务端位置。贴图加载失败时沿用基础画法。
- 地图格子、四座建筑门口和封边由服务端 [`WhiteStoneLayout.java`](../../backend/src/main/java/game/world/WhiteStoneLayout.java) 与现有服务生成。水井和摊位各占一格；栅栏沿服务器返回的封边绘制。白石城样板启用条件为 `QINGYU_WHITE_STONE_SAMPLE=true` 且首次生成二级场景，场景版本为 4。已有场景照常读取。一级地图、普通二级地图、三级室内和场景战斗继续使用既有入口和契约。
- 隔离预览入口是 `http://localhost:5173/`。沿短路线实际走到旅店，点击进入后在原画布开战、切换视角、结束战斗并出门均通过。南侧入口至旅店的 17 格路线已返回；完整行走、真机和前后性能对照尚未验收。实际素材和镜头比概念图简化。2026-11-18 正式服 V36 启用样板，正式服此前没有白石城二级地图存档，玩家首次进入时生成。

## 当前实装 · 探索移动

二、三级地图普通点格只查看详情。先点底部探索栏「移动」进入选择状态，再点目标格才发送 `/scene/move`；旧的选中格不会因点按钮而自动移动。移动使用当次点击的格子与交互组件，保留柜台、设施的邻格落点。取消按钮、Escape、折叠热栏、切换技能、切场景和进入战斗会清理该模式。地点卡保留非移动交互及停止入口。真实浏览器已在桌面和手机横屏核对选格零提交、进入模式零提交、取消零提交、目标单次提交及实际到达。详见[图鉴销毁与移动模式记录](../superpowers/plans/2026-11-19-codex-disposal-and-move-mode.md)。

图鉴插画通过局部 Pixi 渲染器导出。销毁该临时渲染器，以及大陆和局部场景的渲染器时，必须使用局部资源释放选项 `releaseGlobalResources:false`，避免 Pixi 全局批次资源被正在运行的其他画布继续引用。已验证五类图鉴、反复开合和地图拖动，并覆盖正式构建与 CSP 下的隔离页面。
