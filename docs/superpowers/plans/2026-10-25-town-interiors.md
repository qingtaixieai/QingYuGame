# 城镇建筑与室内服务实施计划

> 实施使用 executing-plans；各模块完成后独立只读代理审查。用户已对本范围确认“可以”，继续不重复询问。

Goal: 实现真实共享室内、门、服务NPC、进店交易与5铜10秒旅店，完成整阶段本地验收。
Architecture: TownService保存建筑/门/服务角色；SceneRuntime执行实际场景移动；BattleService按scene_id隔离并复用门撤离；ProductionService复用持续单槽预留结算旅店费用。
Tech Stack: Spring Boot/PostgreSQL、React/TypeScript/SVG。基线c30bc4d；沿用隔离开发分支。
Spec: 设计决策总账第5、14节及设计补齐与实施交接；本次用户确认范围。

## 约束与实施选择
- 商店、工坊、铁匠铺、旅店开放；民居不开放。入口/室内持久存储，重进不重新生成；各门有固定端点，不用菜单跳任意门。
- 门口占据时仅在该门2格内沿合法通路寻找空位；无位置拒绝切换。此距离为当前实现常量，可配置扩展，不改变已确认附近落点规则。
- 室内保持进入时一级归属；退出真正跨区域再变更。按实际场景开战，室内不封一级道路。
- 商人/旅店老板为可战斗服务NPC，服务检查其存活及所在室内；同场景战斗暂停服务。工匠死亡不禁用公共设施。默认5分钟重生，落点不足等待；不远程服务。
- 旅店5铜等值，10秒满HP，不解状态/不改绑定；复用production单槽与材料预留，静止、非战斗、玩家在线，完成扣费，中断释放。沿用现有CoinPayment按实物钱币支付并找零，不合并为虚拟余额。
- 仅完善已确认范围，不新增官方后勤/执法/复杂城镇多地块自动规划。已有城镇所在地块生成4栋服务建筑，既有地形不重生成；安全摆放需要避开角色、资源与出口。
- 不推送/部署；最终说明本地验证和未覆盖项。
