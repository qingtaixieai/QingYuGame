# 青屿地块丰富度与采集动效开发计划

**目标**　用固定种子的像素装饰和少量地形交互丰富现有地图。同一地块的构图对所有玩家一致，回访时可以认出。

**状态**　用户已确认开工。首版改动已在本地实现，正式服基线为 V32。

## 地图内容

| 地形 | 装饰小景 | 可用交互 |
| --- | --- | --- |
| 平原 | 花簇、矮草、碎石边 | 拾小石头、采纤维 |
| 森林 | 林缘、蕨丛、倒木、树桩 | 砍伐树木、采纤维 |
| 丘陵 | 岩脊、碎石坡、低矮灌木 | 开采铁矿 |
| 水岸 | 芦苇、漂木、岸边小石 | 在可达陆地使用该地形已有的采集类型 |
| 城镇 | 路旁花坛、路标、空木箱、铺面陈设 | 门、柜台、设施等现有交互 |
| 室内 | 按房间用途组合地毯、家具和沿墙陈设 | 保留门、休整、制作等原有入口 |

一级地图用轻量小景表达地形差异。二级地图组装完整小景，三级继续复用局部地块组件。以场景或世界地块身份和坐标派生固定种子，按地形与空间条件选模块。同格可共存多个组件，并沿用各组件的独立显示偏移和命中。图鉴的地块卡仍只绘地面，交互组件沿用自己的图鉴条目。

## 已有地图增补

- 纯装饰按固定种子绘制，位置受道路、门口、出口、交互标记和地形约束。装饰不拦截点击，也不影响通行或战斗判定。
- 后端按内容版本做幂等增补，新交互只选合法空格。原有地形、封边、门、资源对象 ID、刷新状态与角色位置保留。
- 城镇主街和广场优先表现为城镇空间。新加的木箱、木堆等装饰与真实采集点有明确外观差异。旧采集点先保留，若有影响城镇构图的实际案例，记录后再决定是否迁移。
- 本轮复用已有采集动作、工具限制和刷新规则。待定机关和新的资源产出继续留在设计总账。

## 采集动效

- 延续一级地图已有的短幅左右晃动。砍树、采矿、采纤维在服务端确认任务进行时，只晃正在采集的那个对象。取消、中断或完成时恢复原位。
- 即时拾取的小石头在成功时播放一次短晃动，再按已有规则消失。失败保留原状态。
- 同一场景其他玩家能看到进行中的采集。短动效复用 Pixi 动画更新，按需渲染，不因对象晃动重建地形。

## 分工与验收

| 责任 | 交付与检查 |
| --- | --- |
| 场景与美术 | 为平原、森林、丘陵、水岸、城镇和室内各核对样图；检查道路和角色是否清楚可读 |
| 后端 | 校验新旧地块增补、位置稳定、重复加载无重复对象、合法路径、工具和资源结算 |
| 前端 | 复用 Pixi 图层与同格组件；实际检查动画开始、结束、中断和即时拾取 |
| 独立验收 | 每阶段复核，明确区分静态审查、隔离库和真实页面结果 |

在隔离库验证固定种子、新旧地块、道路门口、同格多组件、两个客户端一致、采集取消及资源刷新。浏览器覆盖 1280×800 和 844×390，录制采集时的帧间隔，并对比地图加载性能。代码与接口结构改动后运行工程检查。

## 本地验收记录

- 临湾镇截图对应的旧放置公式按 `31 × q + r` 单调排序。旧代码在隔离库复现五个资源点同列，坐标为 `q=-13, r=3…7`。新生成资源按地形匹配、固定种子和至少三格间距布置。
- 内容版本增补保留旧对象位置与状态。旧城镇优先补画面，截图中的既有资源行尚未搬动。
- 两阶段独立静态复验通过。最新版生产和城镇后端回归 24 项通过，前端构建和工程检查通过。浏览器 1280×800、844×390 均验证采集晃动、取消停帧、石头拾取短晃以及采集过程中不重建地形。
- 本轮浏览器采样使用隔离环境，尚未执行手机真机、两客户端同看采集，以及完整地形和室内样图验收。改动尚未推送或部署。
