# 战斗撤离格视觉调整

已按用户确认在本地实现。

## 目标与范围

- 去掉撤离格逐格重复的「撤离」「封闭」字样。开放格用浅白色、封闭格用灰色，所有外圈格子的底色及常驻轮廓均半透明。
- 范围包括室外新增外圈和室内门外格。保留地底浮现动画、鼠标悬停与移动高亮，以及玩家站上开放格后出现的撤离操作。
- 本次只改前端绘制，撤离条件、地块通行和后台接口沿用现有规则。

## 代理讨论与分工

外部只读代理建议移除逐格状态标签，并核对底色、方向标识和高亮可能叠加的问题。主代理核对各绘制分支，前端负责撤离格视觉，独立验收负责对照开放与封闭格和现有撤离反馈。

## 阶段与验收

1. 调整 Pixi 原场景外圈和相关重复绘制，使动画完成后的开放、封闭格都保持半透明。
2. 前端构建后在桌面 1280×800、横屏 844×390 查看实战画面。确认室外成圈、室内门口、无逐格文字、开放和封闭能看出区别，以及撤离按钮仍能出现。独立复验通过后记录本地结果。

## 追加范围 · 战斗结束与命中反馈

- 战斗结束后，撤离格在原画面下沉、淡出。立即停止响应撤离操作。若玩家同时跨场景，短暂保留原画面的退出过渡，结束后随原场景清理，避免把旧外圈画到新地图。减少动效模式直接切换。
- 火球从屏幕外落下，在陨石接触目标格时播放受击反馈，随后弹出伤害数字。空格只播落地特效；致死或最后一击结束战斗时也要保留落点反馈。其他伤害数字在各自命中后开始播放，不套用陨石的下落时长。服务端伤害结算与回合推进照旧。
- 开工后用浏览器 Performance 分别录制砸空格和砸中角色。现已确认受击、陨石与伤害数字走不同的前端更新路径，有多处 render 调用；它们是否实际造成卡帧，需用录制确认。按结果处理重复渲染及伤害文字的重复创建。
- 特效岗位审查结论为把伤害展示绑定到陨石实际着地帧。验收岗位补充切图、结算最后一击和冲击期间结束战斗的用例。主代理保留空砸动效，并以录制帧时间和画面顺序验收。
- 验收记录需覆盖纯未命中、空砸、命中、致死、最后一击结束、外圈下沉和切图。桌面与横屏分别核对，记录性能样本的环境和前后差异。

## 追加范围 · 左上角地图标题

- 地图左上角的标题框（例如「青屿大陆」）固定在侧栏关闭时的位置。侧栏打开时盖住标题框，标题不再跟随侧栏右移；侧栏收起后原位显示。沿用现有手机横屏隐藏规则。
- 前端调整标题与地点卡共用的选择器，仅让标题退出随侧栏移动的规则。验收核对各级地图标题、开合过渡和宽标题无残边。


## 本地验证

- 前端构建通过，工程检查覆盖 153 个归属源文件与 88 条路由，零错误。外部静态复核给出 PASS。
- 桌面和横屏的陨石命中样本中，着地与伤害数字的首帧时间相同，空格落地不显示数字。伤害文字每次创建一次，与陨石和受击着色共用同一动画循环。最终实测中命中片段最大帧间隔约 17 毫秒，为本机 Edge 无头样本，未建立同场景的旧版帧时间基线，不能据此推断真机差异。
- 两种尺寸均确认最后一击结束战斗、伤害数字仍按着地帧出现，外圈下沉后清除。桌面确认标题原位并被侧栏覆盖。截图验证使用室外场景，室内沿用相同的外圈图层，未单独浏览器实测。
- 未部署，未推送。

## 2026-11-16 撤离格不透明度预览

本地已实现。白色开放格和灰色封闭格稳定时的填充不透明度都由 75% 调至 95%，描边与浮沉动画沿用当前参数。

外部前端与验收岗位确认填充与描边、动效分开控制。用户指定灰格与白格同步调整，采用共用填充值。桌面和横屏浏览器实测两种填充均为 0.95，浮现、下沉和构建通过，独立复核无阻塞。预览为 `127.0.0.1:15195`，未部署正式服。

### 75% 透明预览

用户确认白格和灰格都要 75% 透明，即填充 `alpha: .25`。项目已应用该值。桌面和横屏实测两种填充均为 0.25，并验证浮现、下沉。描边沿用原参数。

### 格缝美化预览

待确认应用。范围为战斗撤离格的显示层。半径由 34 调到 35.5，格距和点选几何仍采用场景原坐标。描边由 2 调到 1.15，描边不透明度由 55% 调到 50%，让格与格更贴合并保留细分隔线。

外部地图与验收岗位建议测量填充与描边参数，分开检查浅色与灰色格，并复测两种尺寸与浮沉。主代理复核相邻中心距离为 √3 × 36，预览半径小于 36，填充面之间仍有窄缝。临时浏览器在桌面和横屏确认填充 0.25、描边宽度 1.15 及浮沉效果，前端岗位待确认后应用原参数修改，主代理跑构建并交独立验收。

2026-11-17，Claude Sonnet 4.6 通过视觉 API 比较了三张横屏战场截图。它认为 35.5 半径和 1.15 描边的窄缝试样在白灰交界更容易显得发虚，建议保留已确认的 75% 填充透明，先截中间方案对照。中间方案采用半径 35、描边宽 1.5、描边不透明度 50%。验收重点是白灰交界与六角顶点在静止和拖动时是否连续清楚。中间方案尚无截图，本轮只讨论，未修改绘制代码。

用户随后确认开工。折中方案已应用于共享 Pixi 画布，原地浮沉沿用现有实现。前端构建与工程检查通过。桌面 1280×800、横屏 844×390 在隔离地图样例中验证填充、描边、拖动及浮沉，Claude Sonnet 4.6 对两张截图复验通过。本地 PostgreSQL 启动命令被执行策略拦截，未进行真实联机战斗验证。

Claude Fable 5.1 随后复看同一组桌面与横屏截图。灰格通常比白格容易区分，白格遇浅草地、灰格遇棕色地表时，轮廓辨识度会下降。部分相邻灰格的接缝疑似有较重的双线，仅凭截图未确认。建议维持 75% 填充透明，下一轮如需改动，先确认相邻格接缝是否叠线，再针对性调整边线。该复看未改代码，也未覆盖真机与联机实战。

### 回退折中方案

用户确认回到格缝美化前的样式。共享 Pixi 画布恢复半径 34、描边宽度 2、描边不透明度 55%。白色开放格和灰色封闭格均保持 75% 填充透明。前端构建通过，桌面 1280×800 和横屏 844×390 的隔离地图样例验证了白灰格样式、拖动、浮现与下沉。未覆盖真机或联机实战，未部署、未推送。

独立验收代理复跑了两种尺寸的浏览器样例，确认绘制参数及动画行为，未发现阻塞问题。
