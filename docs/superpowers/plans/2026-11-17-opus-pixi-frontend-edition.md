# 青屿 · Opus 前端改造版开发方案

**状态**　用户确认以白石城正俯视效果图为参考，已交付本地可运行的第一版。阶段复验范围见文末。

## 本版目标

在现有青屿前端上完成一版可登录、进入实际地图并操作的改造版。以[前端设计与实拍基线](../../engineering/青屿前端设计说明.md)和当前 React、TypeScript、PixiJS 8 工程为基础。允许较大幅度地改界面版式、画布图层、场景构图、镜头和交互呈现。原地图、行走与动作接口、战斗规则和账户数据继续作为实际运行基础。预览在隔离环境交付。

## Opus 意见与主代理取舍

Opus 查看了白石城、旅店和同图战斗实拍，对照 `Game.tsx`、`SceneView.tsx`，建议重新组织地点操作区、入城镜头、室内分区和横屏工具。采用其「入口 → 主街 → 地标」构图和窄屏地点卡按需展开方案。探索热栏沿用用户确认的下方折叠入口，地图工具沿用右侧，战斗保留上方顺序条及下方动作栏。性能用同机样本复测；Opus 方案提到的固定帧率、内存和百分比指标暂无基线支撑，先记录实测结果再定标准。

## 范围、分工与阶段

| 阶段 | 分工与修改范围 | 交付与验收 |
| --- | --- | --- |
| 1. 地图布局和操作 | Opus 负责界面方案及候选补丁。客户端集成岗负责 `features/game/Game.tsx` 与横屏样式，地图岗负责 `PlaceActions`、`MapChrome` 和 `SceneView`。 | 保持地图为主界面。大陆、城镇、旅店共用地点操作层，主要动作随位置变化，详情按需展开。桌面和横屏检查侧栏、顶部横栏、地点卡、地图工具及探索栏，进入、通过门、返回的流程可用。 |
| 2. 地图构图和像素绘制 | Opus 负责构图与视觉补丁，地图岗负责 `localSceneArt.ts`、`sceneModules.ts` 和 `SceneCanvas.tsx` 的绘制集成。 | 一级延续现有青屿地图的海岸、道路和聚落语言。白石城以入口、街道、广场和旅店建立方向。旅店突出门口、柜台和休息区，格内墙与边封路使用能对上通行状态的画法。交互组件仍可按格子组合与偏移。 |
| 3. 同图战斗与整体验收 | 战斗岗负责 `BattleView`、`Hotbar` 和选格呈现；主代理集成。独立验收岗审查执行和截图。 | 在局部场景开战后沿用原 Pixi 画布，验证顺序条、动作点、移动预览、攻击选格、结束回合及查看大世界。白灰撤离格沿用 75% 填充透明、半径 34、宽 2 的已确认样式。 |

主代理控制代码写入与集成，Opus 通过已验证的外部 API 基于源码返回设计与具体补丁，再看真实运行截图复验。阶段一和二的截图各自通过独立验收再继续。正式上线和推送依据项目授权执行。

## 验收场景

- 真实前端连接隔离后端，在 1280×800、844×390 从大陆进白石城、沿街找到旅店、进入房间、开战、切大世界、结束战斗并按入口返回。记录画面与实际交互，覆盖鼠标悬停和横屏触控模拟。
- 在同一分辨率和场景重复采样拖地图、地点选格、切场景和战斗特效。记录帧间隔 P95、长帧数及控制台异常，区分模拟窗口与手机真机结果。
- 运行前端构建。改动模块归属或接口时跑 `python scripts/engineering_check.py`。后端行为变化另行确认，回归只在隔离库执行。

## 本地第一版实现与复验

1. 地点操作卡在桌面和横屏统一置于右上。主要动作和格内组件保持可达，详情默认收起。删除用于将旧卡片推到热栏上方的尺寸监听。Opus 复验代码及两类尺寸截图通过。多组件叠加的实景交互尚需另测。
2. 白石城入城相机将人物入口、实际广场标记与旅店门纳入首屏。屋顶使用俯视瓦片、屋脊和烟囱，广场及外围增加石板和树冠。Opus 复验构图通过，并记录瓦片、建筑装饰和室内家具精细度与参考图仍有差距。路径和门坐标来自现有场景数据。
3. 同图战斗把尸体入口和弹药选择并排，保留原回合条与热栏。Opus 复验结构和双尺寸截图通过。隔离库浏览器从大陆进入城镇、旅店，发起战斗后切往大世界再返回，原旅店 Canvas 节点保持一致。核对结束回合按钮可见；未执行攻击、完整行走路径或真机测试。截图使用临时玩家，夹具预置了进城和进门位置。

前端构建、工程检查（158 个归属源文件、88 条 HTTP 路由）及两种尺寸的浏览器样本通过。尚未建立本版与改造前同场景的帧率对照。Opus 的三个阶段意见和截图复验均由独立 API 请求完成，浏览器由主代理运行。正式服与 GitHub 未更新。
