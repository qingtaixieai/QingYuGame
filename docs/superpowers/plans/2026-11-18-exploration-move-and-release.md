# 探索移动入口与发布计划

**状态**　移动改动已通过隔离验证，于 2026-11-18 随 V36 发布。用户已授权直接上线白石城。当前实装见[前端设计说明](../../engineering/青屿前端设计说明.md)。

## 用户操作

二级和三级场景点击地块后，高亮选中的格子并显示地块详情。点底部探索栏「移动」时，以当前选中的格子为目标发送移动。无目标、无可达路线和连接异常时沿用现有提示与校验。门、柜台和设施沿用已有落点或相邻可达格规则。停止、进门、休整、制作及其他当前可用的交互沿用原入口。移动中先停止，再重新选点并点「移动」。一级大陆和战斗各有自己的移动入口。

## 代理意见、取舍与分工

- 只读前端代理核对了 `SceneView.tsx`、`Hotbar.tsx` 和一级 `Game.tsx`。地点卡的「前往这里／走到门口」「改往选中地点」「走到柜台附近」目前可以直接发移动；探索栏「移动」目前只显示提示。一级大陆没有同一个探索热栏。
- 主代理将局部探索开始移动的入口收敛到 `SceneView.tsx` 的热栏回调，复用选格、路线校验和 `/scene/move`。点击格子仍可做只读路径检查以判断可达性，提交移动只发生在热栏动作。复用当前的探索、战斗选格边界与后端校验。
- 客户端地图岗位负责接入和清理旧按钮。独立验收岗审查点击、请求次数及边界。主代理更新文档并核对发布版本。

## 验收与发布

1. 浏览器用隔离档在 1280×800、844×390 检查点击地块显示详情且角色位置不变。点热栏后只发一次 `/scene/move`。覆盖普通格、整格墙、门口、柜台邻格、移动中停止、切场景以及无目标提示，复验一级和战斗现有入口。
2. 前端构建、相关回归及独立验收通过后准备上线。检查现有 Git 和正式服基线、核对本次发布包含的前后端变更及数据库迁移，再按项目发布流程发布与冒烟。正式服核验健康、版本、静态资源与现有账号入口。
3. 白石城的新样板生成器随版本发布。若正式服预检发现已有白石城场景，先按已有角色、门、设施、战斗和地上遗留物核对迁移范围。若没有白石城场景或本地活动战斗，可直接启用生成器，让玩家首次进入时生成样板。

## 2026-11-18 实现及正式服记录

- `SceneView.tsx` 的探索热栏是二、三级场景唯一的移动发起入口，地点卡保留进门、设施、停止和状态信息。地图点选会做只读路线检查，提交移动后才绘制实际行走路径。桌面 1280×800 和横屏 844×390 均验证点格零移动请求、热栏一次请求、角色抵达及控制台无页面错误。独立代理审查通过。
- 生产发布前为 V32，白石城二级场景尚无存档，同时无白石城活动战斗。发布时停机重新核对，备份正式库、JAR、入口页和运行配置。启用 `QINGYU_WHITE_STONE_SAMPLE=true`，首次进城会生成版本 4 的样板。其他既有场景从原文档读取。
- V1–V32 Flyway 校验和一致，V33–V36 在生产克隆库回放通过。候选 JAR 也在生产克隆库启动至 V36，实际进入白石城并验证生成一个样板场景及四栋建筑。正式服 V36 生效，账户、世界、战斗和场景记录数发布前后保持 `9 / 1 / 47 / 5`，世界文档哈希一致。健康接口、前端入口及公开 JS/CSS 和本地产物逐字节匹配。线上未使用测试账号触发新场景生成。
