# 图鉴销毁修复与探索移动选格

**状态**　2026-11-19 已完成修复、隔离验收并正式发布前端。

## 已复现问题

进入白石城后二级地图保持运行，打开图鉴会出现 `Cannot read properties of null (reading 'clear')`，堆栈位于 Pixi `DefaultBatcher.break`。桌面 1280×800 与横屏 844×390 均复现。

图鉴插画在 `CodexCardArt.tsx` 中创建独立 Pixi Application，导出图片后调用 `app.destroy(true, {children:true})`。当前 Pixi 版本把该参数解释为同时释放全局共享资源池，运行中的场景随后使用失效绘制批次。仅在浏览器临时拦截中换成 `app.destroy({removeView:true,releaseGlobalResources:false},{children:true})` 后，两种尺寸打开图鉴和切换五类条目均未再出现原异常。该对照验证没有改动仓库代码。

## 代理意见与实现范围

- 图鉴审查代理建议先区分目录数据与图形上下文故障。主代理根据上述错误堆栈、Pixi 源码及两组对照确定为全局池销毁问题。修复图鉴临时渲染器的释放方式，核对同页多 Pixi 画布的相关销毁边界，继续释放局部对象和画布。保持现有插画与目录接口。
- 地图审查代理建议增加明确的探索移动选格状态。主代理采用「点探索栏移动 → 点目标格直接开始移动」；普通模式点格只看详情。点移动时旧的选中格不会自动提交。使用此次点击的目标格和组件计算相邻落点，复用现有寻路接口和角色校验。
- 无效格可以继续重选。取消、Escape、切换法术或攻击、折叠探索栏、进入战斗与切场景均清理移动选择状态。提交后回到普通模式。战斗和一级大陆继续走已有移动规则。

1. 前端美术岗处理图鉴释放，地图岗处理 `SceneView` 和共用选格入口；主代理集成并维护文档。避免同时修改同一文件。

3. 验证普通点击零移动请求、点移动零请求、随后点目标仅一次移动请求、实际抵达、取消后只显示详情，以及墙、门、柜台相邻格与互斥技能选择。
