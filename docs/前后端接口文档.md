## 2026-10-26 当面交接与执法增量（本地验收通过，未上线）

迁移V25–V27，不修改既有已应用迁移。所有写入口须审批账号、现有会话及请求校验，WorldService世界锁和数据库事务共同串行结算。

|入口|请求|行为|
|---|---|---|
|GET /handover|无|最近20份参与的报价，含双方名字、state、lines（code/name/quantity/price）、corpses（id/name/price）；读取前清理失效邀请|
|POST /handover/offer|recipient、mode=gift/sell、lines:[{code,quantity}]、corpses:[UUID]、requestId|同实际场景相邻，预留交出方物品和逐具空尸体；出售使用配置售价。NPC按配置缺口选择接收，其余拒绝；无需求不自动收下|
|POST /handover/accept|offerId、lines:[{code,quantity}]、corpses:[UUID]|仅接收方确认，可减少数量/种类；钱物及交出方战斗1AP原子结算。相同接收内容重放返回原结果；变更已完成内容拒绝|
|POST /handover/cancel|offerId|双方均可取消待确认报价，释放预留；不扣钱、不扣AP|
|GET /law/stations|无|当前实际场景的执法人员与公告栏坐标、势力名称、服务状态|
|GET /law/{stationId}/board|无|需在公告栏1格内；返回本势力合并通缉名字、种类/外观代码、原因、银币奖励，不包含位置。战斗中仍可读|
|GET /law/{stationId}/corpses|无|需在执法人员1格内、人员存活、该场景无战斗；列背包中本势力有资格的空尸体及死亡前记录数|
|POST /law/claim|stationId、corpseId、requestId|重新校验携带、服务与未预留；一次性收尸、加实体银币、只清该尸体保存的对应势力记录ID；请求重放不二次发奖|

- `reserved_quantity` 同时计算制作预留与待确认交接。装备、使用、丢弃和出售不能消耗预留物；尸体预留期间不可剥皮、丢弃、出售或兑奖。
- 战斗交出方必须当前回合且至少1AP；接收方不要求当前回合。回合切换立即取消未成交交接；脱离相邻、切场景、死亡、断线、重启也失效。
- NPC使用同一距离、数量、回合和成交链；首批无限付款权限只用于真实出售结算，不写无限背包余额。需求来自`npc_supply_targets`，默认无需求则拒绝；完整NPC决策和配送另阶段实现。
- `battle_actors.handed_over/sprinted`保留双向互斥状态。现有版本尚无快跑动作处理器；将来接快跑必须校验`handed_over`，不得只加前端按钮。
- 有效非法预设、实际攻击和敌对打断记罪，非法请求事务回滚不留罪。战斗援助对抗合法攻击者的通缉/恶意目标记罪；战外治疗不记罪。
- 名字显示会附加当地“通缉”标识，真实账号名不修改。犯罪按势力分开保存，离开该势力连续30分钟清除；重入重置离区时间，断线不等于离区。
- 玩家死亡产生独立空尸体以承载死亡时领奖资格，保留背包与装备；死亡位置保留，不再立即传送绑定城镇，主动灵魂回城仍走计时。NPC继续使用原尸体/掉落链。
- 首批区域初始化为“青屿”单势力，城镇/村庄执法，野外不新增犯罪；`jurisdiction`允许同格多个势力，现有配置不按城镇拆罪。此为基础数据默认值，不代表多势力地图编辑器或范围显示已完成。

- 每个实际 scene_id 至多一场活动战斗，同一一级格不同房间可各自战斗；室内战斗不封一级道路。进入室内保留进入时世界归属，从室外门实际离开再更新。

- V24新增 town_buildings、town_doors、rest_payments；生产任务支持rest；预留和付款明细随任务删除级联释放。活动战斗唯一性按scene_id区分，legacy空scene保留世界格唯一约束。
- 首期每个城镇/村庄地块创建四栋服务建筑，普通房间半径4、制造房间半径5；不是完整多地块城镇生成器，也不代表住宅、执法或后勤已实现。

## 0. 阅读指引

- 2026-10-09用户确认：NPC与玩家能共用的规则尽量共用；AI负责选择动作，不绕过同一动作处理器和合法性校验。必要差异需明确说明。本轮修复共享完整攻击范围、行动点费用和绷带处理；NPC与玩家都执行回合超时。玩家离线判断仍只适用于玩家，NPC不依赖浏览器连接。
- NPC回合先检查超时，再调用AI；武器候选使用实际形状、费用、装备攻击能力及完整战场边界。AI动作若被业务规则拒绝，记录原因并结束本回合；数据库或程序异常不作为正常拒绝吞掉。本轮未新增HTTP路由。

- 后端是**单一权威世界拥有者**：世界与战斗写操作主要由 `WorldService` 的 `synchronized` 监视器协调，并按服务实现使用事务；聊天、账号等有独立服务/事务边界，不能认为所有接口共享同一全局锁。
- 前端**只用两条通道**：HTTP `/api/*` 发命令（有返回值），WebSocket `/ws` 收状态（**只读**）。
- 所有**时间**除聊天 `createdAt` 外都是 **Unix 毫秒（epoch ms）**；`createdAt` 是 ISO-8601 字符串。
- 所有**坐标**是**轴向六角坐标 `(q, r)`**；距离 `distance(a,b) = max(|Δq|, |Δr|, |Δq+Δr|)`。
- 「权限」列含义：**P** = 已登录（会话有效）；**A** = 已获批准进入；**M** = 管理员。定义见 §2.1。

## 1. 系统总览与数据流

```
浏览器 (React + PixiJS)                    后端 (Spring Boot, 单进程)
  │  fetch  /api/xxx  ──命令(带 X-World-Request)──▶  Controller ──▶ WorldService(锁+事务) ──▶ 各 Service ──▶ PostgreSQL
  │  ◀── JSON 响应 ───────────────────────────────┘
  │
  └─  WebSocket  /ws  ◀──服务端主动推送 state/chat-changed────  WorldService.broadcast()
```

- **命令走 HTTP，状态走 WebSocket**。WebSocket 不接受客户端消息（发了会被服务端以 `1008 POLICY_VIOLATION` 关闭）——所有变更都必须走带 CSRF 头与同源校验的 HTTP。
- 上图简化展示世界命令通路；聊天、账号管理并非所有请求都经过 WorldService，具体事务边界以对应服务为准。
- 一个后台定时器 `@Scheduled(fixedDelay = 350ms)` 调用 `WorldService.advance()`，推进：世界移动步进、角色计时器/复活、怪物游荡与开战/增援、渡船航行、资源恢复、战斗 AI 与超时、遗留物过期，并在需要时广播。
- 生产环境由 Nginx 反代：`/api`、`/ws` → 后端；其余 → 前端静态资源。本地开发用 Vite(5173) 代理到后端(8080)。

## 2. 通用约定

### 2.1 鉴权与三档权限

登录成功后服务端下发 Cookie：

```
WORLD_SESSION=<43位base64url令牌>; Path=/; HttpOnly; SameSite=Strict; Max-Age=604800[; Secure]
```

- 令牌在库里以 **SHA-256** 存储（表 `sessions`），**每个账号只保留一个会话**（新登录会顶掉旧的）。
- 服务端用 `accounts.require(req, needApproved, needAdmin)` 统一判定：

| 调用 | 含义 | 失败时 |
| --- | --- | --- |
| `require(req, false, false)` | 仅需有效会话 | 无/过期令牌 → **401** `请重新登录，或检查用户名和密码` |
| `require(req, true, false)` | 需已获批准进入 | 未获批准 → **403** `账号尚未获准进入，或权限已被撤销` |
| `require(req, true, true)` | 需管理员 | 非管理员 → **403** 同上 |

- 任意时刻若账号/IP 被封禁（`scope=game`），也会 **403**。聊天相关接口另有 `scope=chat` 禁言判定。
- 账号规则：用户名 2–24 位（文字 / 数字 / `_` / `-`）；密码 ≥10 字符且 UTF-8 ≤72 字节；密码用 BCrypt(强度 11)。**新注册账号 `approved=false`，需管理员批准才能进入世界。**

### 2.2 请求守卫（`RequestGuard` 过滤器）

对所有请求统一生效：

- 非 `GET`/`HEAD` 请求**必须带请求头 `X-World-Request: 1`**；若同时带 `Origin`，则必须与配置的 `app.origin` 一致。否则 **403**（这是防 Cookie-CSRF 的手段）。
- 请求体上限：普通接口 **16 KB**；`POST /api/chat/image` **6 MB**；超过 → **413**。
- 对 `POST /api/login` 与 `POST /api/register` 按来源 IP 限流：**每分钟 20 次**，超过 → **429** 且带 `Retry-After: 60`。
- 所有 `/api` 响应带 `Cache-Control: no-store`。

### 2.3 统一错误格式

业务异常通常返回 `{"message": "..."}`（HTTP 状态码表达类别）。`RequestGuard.sendError`、容器及代理层错误不保证此 JSON 结构；客户端须兼容非 JSON 错误响应：

| 状态码 | 含义 | 典型 |
| --- | --- | --- |
| 400 | 参数/规则错误 | 坐标无效、行动点不足、不能攻击自己 |
| 401 | 未登录/会话失效 | 令牌无效或过期 |
| 403 | 无权限/被封禁/守卫拦截 | 未批准、非管理员、缺 `X-World-Request` |
| 404 | 记录不存在 | 账号/图片不存在 |
| 409 | 冲突 | 用户名已被使用、快捷栏 revision 过期 |
| 413 | 体积过大 | 请求体超限；ChatService 检测到图片超过5MB时为400 |
| 429 | 限流 | 登录过频、发消息过快、表情过快 |
| 500 | 未预期错误 | — |

### 2.4 坐标、方向与时间

- 六角方向序固定为 `[(1,0),(0,1),(-1,1),(-1,0),(0,-1),(1,-1)]`，索引 `0..5` 对应名称 `东/东南/西南/西/西北/东北`（用于战斗外圈边缘与撤离方向）。
- 战场是以战斗格为圆心、`RADIUS = 6` 的六边形；外圈即「距离恰好等于 6」的格子。
- 时间统一 epoch 毫秒。

## 3. WebSocket 协议

### 3.1 握手与鉴权

- 地址：`ws(s)://<host>/ws`（生产经 Nginx，需透传升级头）。
- 握手时用同一 `WORLD_SESSION` Cookie 鉴权；未登录 / 未批准 → 握手返回 **401**，连接不建立。
- 仅允许配置的 Origin。
- 同一账号可多连接；**全局连接数上限 40**，超出时新连接以 `1013 SERVICE_OVERLOAD` 关闭。
- 连接成功会把该账号标记为 `entered = true`（这之后玩家才出现在世界地图上）。

### 3.2 服务端 → 客户端消息

两种消息：

1. **状态推送**：`{"type":"state", ...}`，结构与 `GET /api/players` 的返回**完全一致**（同一个 `snapshot(viewer)`，字段见 §4.2）。
2. **聊天通知**：`{"type":"chat-changed"}`（仅提示，客户端收到后自行去拉 `/api/chat/status`、`/api/chat/messages`）。

服务端在任何写操作后、以及定时器判定状态变化时广播状态。

### 3.3 客户端 → 服务端

- **没有任何允许的客户端消息。** 发送任意文本消息会被服务端立即以 `1008 POLICY_VIOLATION` 关闭连接。所有写操作走 HTTP。

### 3.4 断线与重连

- 同一账号最后一条连接断开时，服务端才取消该用户的移动路线与进行中的计时器（`cancelTimer`）；若其在战斗中，则触发一次战斗版本号变化（离线玩家的预设攻击会在其回合被取消）。
- 前端采用指数退避重连（1s → 10s），每次重连前先 `GET /api/me`：401/403 则进入「权限丢失」流程，否则重连。

| 方法 | 路径 | 权限 | 请求 | 返回 |
| --- | --- | --- | --- | --- |

```jsonc
// WorldMap
{ "version":"<uuid>", "seed":12345, "name":"青屿大陆", "radius":34,
  "spawn":{"q":-3,"r":3},
  "tiles":[ {"q":0,"r":0,"terrain":"plain","road":true,"place":null|null} ] }

// Snapshot（GET /players 与 WS state 共用）
{ "type":"state", "version":"<uuid>",
  "players":[ /* Player[]，见 §5 */ ],
  "tick":12345,
  "resources":[ /* ResourceNode[] */ ],
  "actions":[ /* WorldAction[] */ ],
  "serverTime": 1728000000000,
```

### 4.3 移动、采集与表情

| 方法 | 路径 | 权限 | 请求 | 成功返回 | 主要失败 |
| --- | --- | --- | --- | --- | --- |
| POST | `/move` | A | `{q, r, version}` | `{path: Hex[]}` | 400 坐标无效 / 世界已更新 / 倒地下无法移动 / 战斗中 / 目标格被战斗封锁 / 无法到达 |
| POST | `/stop` | A | `{}` | `{message}` | 400 战斗中 / 倒地 |
| POST | `/collect` | A | `{q, r, version}` | `{message}` | 400 未到该格或未停下 / 战斗中 / 资源恢复中 / 有人正在伐木 |
| POST | `/emote` | A | `{code, version}` | `Emote` | 400 不支持的表情 / 战斗中 / 世界已更新；250ms 内重复 → 429 |

- `/move` 返回**余下路径**并开始按 tick 逐步移动；服务端保证「先落库再广播」，重启不会回退已确认的步。
- `/emote` 的 `code ∈ happy | sad | angry | question | thumb | heart | help | ok`，表情持续 3 秒。
- `/collect`：`stone` 立即 +1（30s 后在别处恢复）；`wood` 先启动一次 3s 的砍伐行动（行动期间不可移动），完成后 +1，树 60s 后恢复。

### 4.4 角色与背包

| 方法 | 路径 | 权限 | 请求 | 成功返回 | 说明 |
| --- | --- | --- | --- | --- | --- |
| GET | `/character` | A | — | `Character` | 当前角色完整状态 |
| GET | `/inventory` | A | — | `Item[]` | **物品定义全列 + 拥有数量 `quantity`**（无则 0） |
| GET | `/items` | A | — | `Item[]` | 物品定义目录（`item_definitions`） |
| POST | `/equipment` | A | `{mainHand, offHand}`（兼容 `{code}`） | `{message}` | 换装规则见 §8.3 |
| POST | `/character/action` | A | `{action, targetId}` | `{message}` | `action ∈ bind / rest / recall / revive / cancel / rescue / bandage / surrender` |

`/character/action` 语义（`targetId` 视 action 而定）：

| action | 前置 | 效果 |
| --- | --- | --- |
| `bind` | 站在城镇格 | 把绑定点设为当前格 |
| `rest` | 站在城镇格 | 计时 10s 后回满血 |
| `recall` | 灵魂态 | 计时 5s 后回到绑定点并复活 |
| `revive` | 灵魂态且站在死亡标记格 | 就地复活 |
| `cancel` | — | 取消当前计时器 |
| `rescue` | 战斗外同世界格；战斗内相邻战术格、自己回合且满6AP | 救起倒地旅人（回5血）；战斗内随后结束施救回合，仍使用此接口 |
| `bandage` | 与目标同格、目标未满血 | 消耗 1 绷带，治疗 4 |
| `surrender` | 战斗中 | 主动死亡并退出战斗 |

### 4.5 战斗

| 方法 | 路径 | 权限 | 请求 | 成功返回 |
| --- | --- | --- | --- | --- |
| GET | `/battle/current` | A | — | `BattleState`（未参战为 `{active:false}`） |
| POST | `/battle/start` | A | `{targetId, version}` | `{id}` |
| POST | `/battle/join` | A | `{battleId, version}` | `{id}` |
| POST | `/battle/step` | A | `{battleId, q, r}` | `{message}` |
| POST | `/battle/attack` | A | `{battleId, targetId? , q?, r?}` | `{message}` |
| POST | `/battle/withdraw` | A | `{battleId, direction, force}` | `{message}` |
| POST | `/battle/end-turn` | A | `{battleId}` | `{message}` |
| POST | `/battle/guard` | A | `{battleId}` | `{message}` |
| POST | `/battle/cancel-guard` | A | `{battleId}` | `{message}` |
| POST | `/battle/bandage` | A | `{targetId}` | `{message}` |
| POST | `/battle/equipment` | A | `{mainHand, offHand}` | `{message}` |

要点：

- 除 `bandage` 和 `equipment`（由服务端读取当前战斗 id）与 `start/join`（用 `version`）外，其余战斗接口都要求 `battleId` 与**当前战斗一致**，否则 400「战斗已变化，请刷新战场」。
- **发起战斗**：只能对自己**同格**且未受保护的角色；该格若已有战斗则只能 `/battle/join`。
- **增援**：必须站在战斗格**相邻格**（`distance == 1`），否则 400（玩家提示「请先到达战斗格旁边」；生物提示「生物需到达相邻格才能增援」）。
- **移动** `step` 走的是战场内的路径，消耗行动点 = 步数；离开「被标记格」或攻击者离开射程时会即时结算预设攻击。
- **预设攻击** `attack`：按武器形状计算覆盖格并存入 `intents`（对他人可见）；同一回合重复标记同一格不重复扣点。
- **`bandage` 战斗内**：耗 2 行动点，治疗自己或**相邻**角色 4 点（不占用攻击）。
- **`end-turn`/`guard`/`cancel-guard`** 语义见 §8.2。

### 4.6 快捷栏 / 技能栏（`hotbar`）

| 方法 | 路径 | 权限 | 请求 | 成功返回 | 失败 |
| --- | --- | --- | --- | --- | --- |
| GET | `/hotbar` | A | — | `HotbarState` | — |
| POST | `/hotbar/layout` | A | `Edit`（见下） | `HotbarState` | 400 操作非法 / **409 栏位已更新，请重新整理** |

```jsonc
// HotbarState
{ "revision": 3,
  "slots": [ {"source":"common","index":0,"actionRef":"move","locked":false}, ... ],
  "actions": [ {"id":"attack:axe","source":"weapon","name":"斧头","icon":"attack",
                "command":"attack","description":"...","cost":2,"costKind":"action",
                "quantity":null,"disabledReason":""}, ... ] }

// Edit
{ "revision": 3, "operation": "clear|swap|assign|lock", "from": 0, "to": 6, "actionRef": "move" }
```

- 栏位分 5 个来源分类：`common | weapon | item | spell | class`，每类初始6个槽，自动填充时可扩展，并非固定上限。
- `from`/`to` 是返回的 `slots` 数组全局下标，不是分类内编号；交换需同分类，`lock` 切换目标槽锁定状态。示例只是字段结构，不表示0与6允许跨分类互换。
- `actions` 是**当前可用动作全集**（由服务端按装备/背包/战斗状态生成），`disabledReason` 非空表示该动作当前不可用及原因。
- `revision` 用于乐观并发：客户端回传的 `revision` 与服务端不一致时返回 409。

### 4.7 遗留物与容器（`loot`）

| 方法 | 路径 | 权限 | 请求 | 返回 |
| --- | --- | --- | --- | --- |
| GET | `/loot` | A | query `version`, `battleId?` | `{ground: Container[], carried: Container[]}` |
| GET | `/loot/{id}` | A | query `version`, `battleId?` | 该容器内含物品行（`loot_items ⋈ item_definitions`） |
| POST | `/loot/action` | A | `Command`（见下） | `{message}` |

```jsonc
// Command
{ "action":"take|takeAll|carry|dropCorpse|dropItems",
  "containerId":"uuid|null", "code":"bandage|null", "quantity":1,
  "version":"<uuid>", "battleId":"uuid|null",
  "items":[ {"code":"wood","quantity":3} ]   // 仅 dropItems 用
}
```

- 前置：必须停下、角色存活、不在船上；**同一世界格**才能查看/拿取（战斗内则要求同一战场格）。
- `action` 语义：`take`（取指定数量）/ `takeAll`（全取）/ `carry`（把**地面尸体**搬进背包）/ `dropCorpse`（把携带尸体放下）/ `dropItems`（丢背包物品生成"掉落堆"）。
- **战斗中成功的 `take` / `takeAll` / `carry` 各消耗2AP**，要求自己的回合；查看不扣点，失败不扣点。`dropCorpse` / `dropItems` 在战斗中拒绝。
- 地面遗留物 30 分钟后过期消失；携带中的尸体暂停计时；再次丢下重置完整30分钟。
- 前端：固定遗留物入口及选中格子的逐实例查看按钮；拿取后刷新容器，拿空自动删除的掉落堆时关闭详情，携带尸体更新为背包状态。
- 玩家死亡**不掉落、不产生尸体**；怪物死亡产生尸体，尸体内容 = 其背包 + 已装备武器（`unarmed`/`claws` 不落）。

### 4.8 渡船（`ferry`）

| 方法 | 路径 | 权限 | 请求 | 成功返回 |
| --- | --- | --- | --- | --- |
| POST | `/ferry/contribute` | A | `{item:"wood"|"stone", quantity, version}` | `{message}` |
| POST | `/ferry/board` | A | `{version}` | `{message}` |
| POST | `/ferry/disembark` | A | `{version}` | `{message}` |

- `contribute` 需站在**望潮港**格；`board` 需站在小船当前停靠岸（会按数量上限截断到剩余需求与背包持有量）。
- 建成条件：木头 8 + 石头 4（可配）。航行相位：`mainland → outbound → island → inbound`；每步 2.5s，两端停靠 30s。航行途中不能下船，靠岸后才能下船。

### 4.9 聊天与图片

| 方法 | 路径 | 权限 | 请求 | 返回 |
| --- | --- | --- | --- | --- |
| GET | `/chat/status` | A | — | `{publicUnread, contacts[], muted, images[]}` |
| GET | `/chat/messages` | A | query `peer?`, `before?` | `{messages: Message[], hasMore}` |
| POST | `/chat/messages` | A | `{peer, kind, body}` | `Message` |
| POST | `/chat/read` | A | `{peer, upTo}` | `{ok:true}` |
| POST | `/chat/image` | A | `multipart/form-data`，字段名 `file` | `{id, status, message}` |
| GET | `/chat/images/{id}` | A | — | 图片二进制（按 `mime` 定 Content-Type） |
| GET | `/admin/chat/images` | M | — | 待审图片行 |
| POST | `/admin/chat/images/{id}` | M | `{approve}` | `{message}` |

```jsonc
// Message
{ "id":123, "senderId":"uuid", "username":"admin", "recipientId":"uuid|null",
  "kind":"text|emote|image", "body":"...", "imageId":"uuid|null",
  "imageAvailable":true, "createdAt":"2026-10-05T12:00:00Z" }   // 注意：ISO 字符串，非毫秒
```

- 历史每页最多40条，`before` 是消息数字ID（只取更小ID），响应按ID升序，`hasMore` 表示还有更早消息。
- 自己的 `images` 行为 `{id,status,mime,size,createdAt}`；管理员待审行为 `{id,ownerId,username,mime,size,createdAt}`，不要混用字段。
- `peer = null` 表示公共频道；不能给自己发私聊（400）。
- `kind ∈ text | emote | image`：text 长度 1–1000；emote 取值同表情码；image 需先上传过一张 `active` 图片。
- 发送限速：同一账号 **700ms** 内二次发送 → **429**。
- 图片上传：必须是**真实**的 JPG/PNG/GIF（服务端用 ImageIO 实测解码），≤5MB，单边 ≤4096、总像素 ≤4000 万、GIF 帧数 ≤500。首个图片直接 `active`；已有 `active` 时新图进 `pending` 等待管理员审批。
- `GET /chat/images/{id}` 权限：本人 / 管理员 / 该图曾被发给当前用户。

### 4.10 管理后台（`/admin/*`，全部要求 **M**）

| 方法 | 路径 | 请求 | 返回 |
| --- | --- | --- | --- |
| GET | `/admin/accounts` | — | `Account[]` |
| POST | `/admin/accounts/{id}/approval` | `{approved}` | `{message}` |
| POST | `/admin/accounts/{id}/password` | `{password}` | `{message}` |
| POST | `/admin/accounts/{id}/items` | `{code, quantity}` | `{message}` |
| GET | `/admin/accounts/{id}/inventory` | — | `Item[]` |
| POST | `/admin/creatures/deploy` | `{species, q, r}` | `{message}` |
| POST | `/admin/regenerate` | `{confirmation:"重新生成世界"}` | `WorldMap` |
| GET | `/admin/moderation/accounts` | — | 账号审核行 |
| GET | `/admin/bans` | — | 封禁行 |
| POST | `/admin/bans` | `{targetType, target, scope, minutes, reason}` | `{id}` |
| POST | `/admin/bans/{id}/revoke` | — | `{message}` |

- **投放 NPC**：`species ∈ bully | claw`（恶霸 / 利爪怪）。校验顺序：种类合法性 → 世界外 → 不可通行 → 已被占；分别返回 400。投放的怪 `deployed=true`（**死后不重生**）；坐标必须**可通行**（海岸/桥可通行，海洋/高山/河流不可）。
- **发放物品**：`code` 为 `item_definitions.code`，`quantity ∈ 1..100`；不允许发放 `unarmed`/`claws`。
- **重置密码**：不能重置管理员自己的密码（400）；会强制该账号下线。
- **重新生成世界**：`confirmation` 必须精确等于字符串 `重新生成世界`。执行后重生世界、所有玩家回出生点、清空战斗/资源/遗留物/渡船并重置怪物。
- **封禁**：`targetType ∈ account | ip`；`scope ∈ chat | game`；`minutes` 为 1…5256000 或 `null`（永久）。不能封禁管理员账号，也不能封禁当前管理员所用 IP。
- 所有管理员操作写入 `admin_audit`。

## 5. 前后端类型契约（TS ↔ Java）

前端类型集中在 `frontend/src/types.ts`；后端为各 Service 的 `record` 或直接返回的数据库行。**除注明外，JSON 字段名与 Java 组件名同名。**

| 前端类型 | 后端来源 | 说明 |
| --- | --- | --- |
| `Hex` | `WorldMap.Hex(q,r)` | 六角坐标 |
| `World` / `Tile` / `Place` | `WorldMap` / `WorldMap.Tile` / `WorldMap.Place` | `Tile.walkable()` 为派生方法，不序列化 |
| `Account` | `AccountService.Account` | 登录/`/me`/`/admin/accounts` 共用 |

## 8. 附录：关键业务规则速查

### 8.1 战斗基础

- 战场：以世界格为圆心、半径 **6** 的六边形；外圈 = 距离恰为 6 的格子（撤离出口）。
- 每回合 **6 行动点**；回合时限 **45s**（`game.battle.turn-ms`，最小 5000）。
- 先攻：`d20 + floor((敏捷-10)/2)`，降序；并列时比敏捷，再比入场序。增援者下一轮才轮到。
- 伤害结算：`有效伤害 = max(0, 伤害 - 护甲)`；若伤害>0 但被护甲吃光则至少 **1**；举盾且还有反应点时，用反应点额外减伤 `guardReduction`（不低于 `guardMinDamage`）。
- 结束条件：战斗只剩 ≤1 名参与者，或无人站立。

### 8.2 战斗行动与消耗

| 行动 | 消耗 | 说明 |
| --- | --- | --- |
| 移动 `step` | 1 / 格 | 走战场内路径；离开被标记格或攻击者离开射程时即时结算预设攻击 |
| 普通攻击 `attack` | 武器 `cost`（默认 2） | 按武器形状标记覆盖格；仅仍存在相同预设时重复标记同格不扣点；旧预设已结算后再预设需重新扣点 |
| 举盾 `guard` | 把 ≤2 点行动点转成反应点 | 需要盾；反应点上限 2；举盾状态可累减伤 |
| 取消举盾 `cancel-guard` | 0 | 清空反应点与举盾状态 |
| 绷带 `bandage` | 2 | 治疗自己或**相邻**站立角色 4 点 |
| 换装 `equipment` | 2 | 换装会取消预设攻击并清空反应点 |
| 救援 `rescue` | 需**满 6 点** | 救起相邻倒地旅人（回 5 血），随后结束回合 |
| 准备撤离 `withdraw` | 0 | 站在对应方向外圈，标记撤离并结束回合，下回合离场 |
| 强制撤离 `withdraw`(force) | 需**满 6 点** | 且本回合开始时就在外圈 |
| 拿取/全部拿取/携带尸体 | 成功时2 | 战斗中经 `/loot/action`；查看免费，战斗内丢弃禁止 |

道具栏点击已持有、已支持的道具直接使用：绷带进入地图选目标；取消留在地图。从战斗背包发起的选目标，取消返回背包。自行目标定义走直接使用分支，目前没有新增这种道具。

### 8.3 装备与武器

- 主手：武器 或 双手盾；副手：仅盾。手部标记 `hand_usage ∈ none/main_one/main_two/off_one/off_two` 决定占手与自动换位。
- 武器：空手（1 格，2 伤）/ 利爪（生物，1 格，3 伤）/ 斧（扇形相邻 2 格，3 伤）/ 长枪（直线 1–2 格，3 伤）/ 流星锤（仅第 2 环，5 伤）。
- 盾：单手盾（被动护甲 +1，举盾额外 -2）；双手盾（被动 +2，举盾 -3，最低可挡到 0）。
- 换装流程：先校验背包持有 → 扣减需要装备的物品 → 把被换下的物品退回背包 → 写 `characters.weapon/offhand`。

### 8.4 生命与生死

- 状态机：`alive → down`（HP 归零）→ 倒地值归零后，**玩家**转 `soul`（回绑定点，可 `/character/action` 的 `recall` 回城或到死亡标记 `revive`），**生物**转 `dead`（60s 后重生，仅自动生成的怪会重生）。
- 复活有 `game.revive-protection-ms`（默认 5s）的保护期；保护期内不被攻击。
- 玩家死亡**不产生尸体、不掉落**；怪物死亡产生尸体（内容 = 背包 + 已装备武器）。

### 8.5 怪物

| 种类 | 显示名 | 造型 | 武器 | 背包 | 游荡 | 重生 | 掉落 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `bully` | 恶霸 | 红 | 斧 | 1–4 石 / 1–4 木 / 0–2 绷带 | 绕老家（投放/出生点）1–6 格 | 自动那只**会** | 背包 + 斧 |
| `claw` | 利爪怪 | 绿 | 爪 | 0–3 石 / 0–3 木 / 0–2 绷带 | 绕自身落点 1–6 格 | **不会** | 仅背包（爪不掉） |

- 怪物在玩家进入**同格**时自动开战；走到**进行中战斗的相邻格**时自动增援。
- 怪物 AI（`MonsterBrain`）：在「攻击 / 用绷带自疗 / 移动」中按评分选最优（分数 >0 才执行），执行走**正常战斗指令**，不自带特权。

### 8.6 资源与渡船参数

- 木头：森林格，砍伐 3s，树 60s 后恢复；石头：平原非铺路格，立即 +1，30s 后在别处恢复。
- 渡船：木头 8 + 石头 4 建成；每步 2.5s，两端停靠 30s。

### 8.7 关键配置项（`application.yml` / 环境变量）

`app.origin`（同源校验）、`app.admin-name`、`app.admin-password`、`app.secure-cookie`、`game.recall-ms`(5000)、`game.rest-ms`(10000)、`game.monster.respawn-ms`(60000)、`game.revive-protection-ms`(5000)、`game.battle.turn-ms`(45000)、`game.chop-ms`(3000)、`game.tree-ms`(60000)、`game.stone-ms`(30000)、`game.ferry.wood`(8)、`game.ferry.stone`(4)、`game.ferry.dwell-ms`(30000)、`game.ferry.step-ms`(2500)。
