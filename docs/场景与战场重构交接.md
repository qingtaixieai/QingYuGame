# 青屿二级、三级场景与 PixiJS 战场

本地分支 `codex/online-scene-pixi-20261110` 从线上 V19 功能提交 `c23acb3` 建立。部署记录位于 `32fd7a8`。初版从 `6cdb578` 选择性移植场景，当前合并版已接回原本地工作树 `codex/persistent-scenes-20261023` 的玩法、接口、工程拆分和封边路线。本分支尚未发布。

## 运行路径

- 一级地图到达城镇格后点击唯一的「进入城镇」按钮，其他地块使用「进入当前地块」。到达建筑的门格后，右上角出现通行操作。室内通过门返回室外，二级地图可返回一级。
- 二级和三级共用 `SceneView`，并与一级地图复用 `LocationCard`。点选六边格后左下角显示详情、路线长度及「前往这里」。三级地图共用 MapChrome 和右侧面板容器。右上角与望潮港共用 `WorldActionPanel`，有图标、标题、说明和当前位置可执行的通行、服务与采集操作。服务器按步推进，前端在收到位置更新时补间显示。地图工具在右侧。
- 战斗仍由后端执行行动合法性、行动点、攻击预设、回合和撤离。PixiJS 画布绘制地形、红格、范围、角色、血量和掉落，顺序条、热栏、战斗记录保留 DOM 控件。战斗中可切到一级地图查看。
- 封边只阻断该边。整格墙体、家具和深水由 `walkable=false` 标记。三级出口位于 `(0,radius-1)`，旧外缘位置不生成格子。每个房间有独立战场。

白石城等城镇的探索画面用 `sceneArtLayout.ts` 将广场和店门连成道路。旅店的门厅、柜台和休息区也由该模块标记。它只改变探索呈现，服务器地图仍决定通行和门的位置。

`sceneModules.ts` 集中定义地块模块和交互组件。用 `stampModule` 按轴坐标平移模块，只覆盖允许的格子；用 `moduleSeams` 查六向邻接，封边优先。白石城广场和旅店门厅已使用该组合方式。

侧栏「图鉴」分为交互组件、道具、怪物、地块。每个条目是带主图、名称和短说明的收藏卡，主图由 CodexCardArt 调用现有游戏绘制逻辑。道具用背包 ItemIcon，怪物和渡船共用 worldArt，地块仅绘制对应地图的地面层。点击显示完整说明。已实现条目可直接查阅。道具来自现有物品定义，一级地块来自大世界地形，二三级条目来自模块定义。组件与地块的关联只在实现中使用，图鉴不反向显示。

## 接口和数据

`GET /api/scene` 返回当前活动场景、角色坐标、格子列表与 `blockedEdges`。封边元素包含 `from` 和 `to` 两个轴坐标。通过 `POST /api/scene/enter|leave|move|cross|door` 改变场景状态，命令带当前世界 `version`。移动返回服务器认可的路径。WebSocket 的 `scenePosition`、`sceneMoving`、`sceneResidents`、`sceneDoors`、`sceneObjects` 和 `sceneLoot` 驱动界面。`GET /api/battle/current` 在分层战场中返回相同地形的 `cells`、`blockedEdges` 和 `sceneLevel`。场景基础由 Flyway V20 至 V24 提供，合并版包含至 V30 的原本地玩法迁移。生成的场景文档随数据库持久保存。

## 原本地版与共享绘制合并

- 原本地版的模块化入口为 `app/App.tsx` 和 `features/game/Game.tsx`。保留其独立 HTTP 控制器、共享协议类型、采集制造、交接执法和 NPC 物流。将图鉴、地图工具、地点详情、右上角场景操作框和 Pixi 战场接到模块化入口。
- 探索选格由 `GET /api/scene/route` 预览服务端路径，点击前往才调用移动。设施请求最近的可达相邻格。实际移动继续由服务端重新验证。历史风格试验素材和入口保存在原工作树。
- 战斗界面从顺序条下方到热栏上方留出画布区域，鼠标选择由 Pixi 画布的格子坐标决定。制作入口随战斗开始收起，战斗交接仍沿原规则。
- 热栏和行动处理器共用战场通行检查。室内实际门格与室外六向边缘分别判断，避免房门可撤离但热栏按钮灰色。
- 战斗换轮在事务内先把参战者放入未被占用的临时顺序，再写入按先攻排序的连续值，并同步下一加入位置。旧数据里的 1 与 10001 可直接跨轮，不需要删除战斗记录或手改先攻。
- 合并预览使用 15178（前端）与 18083（后端），对应独立的 `qingyu_combined_preview_20261110`。数据库回归使用 `qingyu_phase1_combined_20261110`。原预览和原本地数据库各自保留。

## 三层格内组件与战斗提示（2026-11-12）

- 一级、二级和三级共用 `cellInteractions.ts`。每个组件用实际对象 ID 标识，配置 `offset: {x,y}` 或在 `interactionOffsets` 按 ID 登记像素偏移。同格自动安排四枚标记，地点操作区列出全部组件。偏移只用于画面和命中，通行、距离和动作仍由服务端按原格及对象 ID 校验。
- Flyway V31 允许多个局部场景对象使用相同坐标。采集和制作继续锁定所选对象的 ID。
- 三层共用表情轮盘与像素素材，服务端按发出时所在场景分发表情。二三级角色头顶显示表情，切换场景后原场景表情从当前视角移除。
- 开战保留局部场景画布和镜头，脚下光环与战斗栏短过渡尊重系统的减少动态效果设置。血条按服务器给当前玩家的关系着色，敌对红、中立黄、友方和自己绿。
- 独立代理复验了同格及相邻格命中。隔离库实测 V31，桌面和横屏走通同格多组件、城镇和旅店表情、原画布入场与行动，并分别用中立和敌对角色验证关系。大陆港口实测地点与渡船切换及造船详情开合。

## 战斗绘制性能（2026-11-12）

- Pixi 战斗把格子高亮和路线、人物与血条、短暂伤害特效放入独立图层。倒计时仍刷新，只有有伤害特效时才随时间更新特效层。WebSocket 中内容相同的人物、场景居民及战利品列表保留原引用。
- 同一台开发机和隔离库使用 Edge 无头浏览器录制。静止 3.25 秒内，人物所在图层的重建次数在 1280×800 由 14 降为 0，在 844×390 由 24 降为 0。包含选格与实际走位的采样分别由 15 降为 5、24 降为 9。两轮均未复现超过 33.5 ms 的帧间隔，横屏数据不能替代手机真机测量。
- 隔离库浏览器回归通过进城、进旅店、同画布开战、两次点格移动、结束回合及返回场景；另外实测了大世界发起战斗、近战预设、走位触发伤害及浏览器绘制伤害特效。DeepSeek 只读代理复验绘制顺序、交互闭包和特效清理，未发现阻塞项。可在本地预览 15178 试玩，尚未发布。
